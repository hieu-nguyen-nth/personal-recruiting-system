# Capabilities and evidence boundaries

Separate **a designed capability**, **an authored demonstration**, and **an observed integration result**. This kit contains concrete instructions and offline examples. It is not an executable service, a public audit log or a claim that every ideal component is enabled.

## Module packaging

The public kit has six reference skills. A compact implementation can use five installed methods—coordination, evaluation, Company Intelligence, tailoring and QA—with networking handled inside coordination. Splitting those procedures into sample folders improves reuse; it does not establish that every folder was separately installed or independently exercised.

| Area | What this repository supplies | Evidence boundary |
|---|---|---|
| Coordination and resume continuity | Routing, stopping rules and a versioned checkpoint | The case is an authored reference answer, not an autonomous execution transcript |
| Evaluation | Quick/full procedures and two contrasting role decisions | General framework, not personal scoring weights or a universal threshold |
| Company Intelligence | Quick/Basic, Standard, Deep and focused refresh; executive brief + six-section framework | Example excerpts are synthetic, not verified publications or real hiring criteria |
| Networking | Discovery/refresh method and dated conversation storage | Example conversations are hypothetical; no outreach or referral occurred |
| Tailoring and QA | Raw evidence, exact edits, deliberate error injection and correction check | Demonstrates review mechanics; claims are fictional and not usable candidate qualifications |
| Scheduling | Creation/verification procedure, short trigger and maintained scan method | A saved file does not create a task; simulated digests do not prove execution |
| Editable documents / PDF | Ideal architecture and required validation boundary | Optional integration; no document/export implementation or final-file validation is demonstrated here |

## Sanitized implementation experience

Private integration records reviewed while preparing this kit document an actual local scheduled smoke test and a recurring scan, including job-source access, Notion read/write, canonical identity matching and report readback. The operating model also uses linked Jobs/Companies and People-page conversation history. These are integration patterns exercised in a private workspace, not results produced by cloning this repository.

Raw reports, account identifiers, employers, candidate assessments and timestamps are intentionally not reproduced. This is a maintainer-reported summary, not independently auditable public evidence. Changes to a task's destination or runtime require their own later execution observation; an earlier successful run does not prove a changed setup. No laptop-closed/cloud execution, outreach, submission or document-export success is claimed.

## Verify your own copy

1. Replay the case without outputs first; compare decisions and source fidelity, not exact sentences. Deliberately pass draft-r2 to QA without its correction answer.
2. In your private workspace, verify source/evidence reads and a small marked record write/readback using the intended connectors.
3. Create the actual task in the chosen scheduler and observe execution, not merely the configuration card. Verify canonical identity, bounded coverage, deferred cursor and report readback.
4. Retry a completed unit and confirm it creates no duplicate Job, Company, conversation or dated digest. Test an inaccessible required source and confirm dependent work remains incomplete.
5. If document export is enabled, inspect the exact current editable/exported file separately. Do not infer formatting or ATS behavior from content QA.
