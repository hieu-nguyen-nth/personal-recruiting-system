# Use the recruiting workflow

Keep one private recruiting project for shared references and methods. Start one application chat per company/role; continue that chat for revisions and interview preparation. Use a separate chat for maintaining the system or running the overall scan. Notion holds the durable job/company/contact records and each application's saved next step.

This is an organizational recommendation. Chats keep their own transcripts: a new chat must load the job page, coordinator and sources rather than assuming it knows every earlier conversation. A local Codex chat needs the correct project folder; a cloud chat needs connected/uploaded evidence. [Official project guidance](https://learn.chatgpt.com/docs/projects).

## Tailor a resume

Start a new chat in your existing recruiting project and supply the specific job-page link or JD. Use your configured coordinator, or load this kit's generic sample with your private setup note. See the [skill catalog](skills.md) and [artifact guide](supporting-artifacts.md):

> Use recruiting-coordinator for this role: [my job page or JD]. Read the job, company research, my current approved evidence and existing tailoring method. Propose the strongest positioning and show exact original/proposed changes with sources, including supported additional skills. Run independent content QA against the draft, JD and original evidence. Save progress on the job page and stop for my review. Do not edit Google documents, export a PDF, send messages or apply.

No new plugin is needed to organize this request. The skills define the methods; existing service connections provide tool access. Document-generation capabilities can be connected when you choose to use them. Keep candidate material and the completed private setup note outside the generic sharing repository.

## Other requests

| Request | Input | Saved result |
|---|---|---|
| Evaluate this JD | Specific JD/job page | Assessment, sources, unknowns and next action on the job page |
| Evaluate my considering jobs | Existing active-job view | Bounded evaluations, linked digest, remaining work/errors |
| Research this company, Quick/Standard/Deep | Company name/page, optional depth; no JD/resume required | Executive brief, six-section company profile, dated sources and knowledge gaps |
| Save this insight | Finding and source | Dated update on the existing company page |
| Find people / refresh this contact | Company/person and your connection preferences | Sourced identity/connection evidence, uncertainties and suggested next step |
| Log an event / event insights | Event name/date or link, notes and known participants | One Events page with general insights, Companies/People links and sources |
| Log this conversation | Actual notes and person | Dated toggle on the existing People page and current follow-up properties |
| Resume from the saved step | Job page | The next unfinished preparation step, respecting the requested stopping point |

Review/approval is part of using the resume workflow, not permission to submit. A proposal is not a final resume. Content QA does not prove document layout, PDF parsing or an employer ATS result. Update the evidence snapshots if the canonical source changes, and recheck affected text after revisions.

For scheduled discovery, use the selected local or cloud scheduler and verify its first real run before relying on it. A chat organization scheme or saved prompt does not create an automation; see [scheduling](scheduling.md).

## Company Intelligence request examples

> Research [company name or URL] at Standard depth. Use research-company and its six-section framework. Return an executive intelligence brief followed by the profile, with dated sources and explicit unknowns. Focus on understanding the business; do not evaluate my candidacy or search for contacts.

> Refresh the existing company page using this article. Update only affected sections and the current synthesis, preserve earlier notes, and leave untouched sections' review dates unchanged.

Quick/Basic, Standard and Deep are effort levels, not promises of a particular tool. Research-only requests may return in chat; add “save to the existing company page” when persistence is desired.

## Event request

> Log this event and my notes. Link the companies and people I name, keep general insights on the event page and suggest follow-ups without sending anything. Keep individual conversation history in People.

Use the [event template](../templates/event-page.md) or inspect the [fictional event](../examples/fictional-case/outputs/event-page.md). An unknown company/person does not block saving a general event insight.
