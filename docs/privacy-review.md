# Sharing review

The repository is a clean-room workflow kit. Private candidate methods, their scoring weights/targeting strategy, live configuration and account records are intentionally absent. Keep working evidence and generated applications outside this checkout.

Before the initial remote creation, review **every** included file, not just the README. Use an explicit file allowlist when staging. Check document text, links, diagrams and metadata for names, emails, phone numbers, usernames, local paths, school/nationality/background details, real contact records, application histories, private document/database IDs, credentials, resume claims and personal strategy. Review git author/committer metadata as well as file contents. A private repository still needs this review.

For this initial template release, the included material was reviewed as generic workflow instructions, blank templates, prompts and a vector diagram. No private files or prior private git history were imported. `.gitignore` is a secondary safeguard; it does not prevent a deliberate force-add or remove previously committed information.

When adapting or sharing later, repeat the review on both the current files and the history you intend to upload. Automated string/secret checks help but do not replace reading the files. Repository ownership, account name and GitHub activity remain account-level metadata; sanitized contents do not make the owner anonymous.
