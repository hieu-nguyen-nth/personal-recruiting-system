# Worked example

The complete [fictional case](../examples/fictional-case/README.md) replaces the earlier single-bullet illustration. Every scenario fact was invented from scratch; it is not an anonymized or paraphrased real resume.

Read the [candidate evidence](../examples/fictional-case/inputs/candidate-evidence.md) and [full fictional JDs](../examples/fictional-case/inputs/job-descriptions.md), then follow:

1. [Evaluation](../examples/fictional-case/outputs/job-evaluation.md): two openings, one company, one mirror; function and industry fit differ.
2. [Company Intelligence profile](../examples/fictional-case/outputs/company-brief.md): executive brief and six business/product/market/PM sections, with source facts, analysis and unknowns.
3. [People page](../examples/fictional-case/outputs/people-page.md): sourced identity, two hypothetical conversations, current follow-up and unsent draft.
4. [Tailoring](../examples/fictional-case/outputs/tailoring-proposal.md): requirement mapping and exact evidence-backed changes.
5. [Draft history](../examples/fictional-case/outputs/resume-draft.md) and [QA](../examples/fictional-case/outputs/qa-review.md): a deliberately faulty review revision is rejected and corrected.
6. [Scan digest](../examples/fictional-case/outputs/scan-digest.md): two bounded simulated runs, cursor continuation, duplicate skip and expected failure behavior.

The case README includes prompts to replay individual methods and a saved continuation checkpoint. Outputs are authored reference answers; no real sources, records, messages, applications or scheduler runs are created.

The [event extension](../examples/fictional-case/outputs/event-page.md) shows general event insights linked to a company and a speaker without replacing personal conversation history.
