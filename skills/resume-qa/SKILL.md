# Resume QA — generic sample

Read the actual current draft, exact JD and authoritative source artifacts. Evaluate independently of the tailoring rationale: reread raw evidence rather than trusting a proposed edit's summary. Use the user's established QA method when configured. Do not rewrite the whole resume by default.

Check factual fidelity first: personal contribution, dates/titles, metric units/baseline/scope, pilot vs general result, prototype vs production, skill proficiency and confidential content. Then check JD coverage, relevant evidence, clarity and internal consistency. A weakly evidenced claim matters more than a missing keyword. The [fictional example](../../docs/worked-example.md) shows a supported pilot result and an unsupported retention claim.

Return prioritized findings with the exact problematic text, source/requirement, reason and smallest useful correction. Distinguish a source conflict needing user input from an ordinary wording issue. State the review outcome: Ready for user review, Revise, or Insufficient evidence. Do not invent an ATS score, hiring probability or final approval.

Content review can run on text. Assess layout, page count and text extraction only when the exact current file is available and inspected; otherwise label those checks Not assessed. An earlier PDF does not verify a revised draft. Recheck affected claims after user edits. Save which draft was checked, unresolved findings and the next review step without marking an application submitted.
